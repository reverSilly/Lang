# 求值模型设计记录

状态：已定稿（2026-10-24）

前置：[01-comptime.md](01-comptime.md)

## 核心原则

语言只有一个调用原语：**求值一个原型（prototype）**。
函数、闭包、协程、生成器都是这一原语在不同操作符、不同环境下的推论，
不存在独立的"函数定义"机制。

**原型是纯代码，不携带任何状态；环境永远由操作符提供。**

## 五件套

| 机制 | 含义 |
|---|---|
| `^Expr` | 原型：`Expr` 的未求值形态，是一个普通的值 |
| `allocate` | 在当前协程就地求值原型（栈上分配结果空间，立即进入求值） |
| `new` | 拉起一个新协程求值原型（独立栈、独立环境，立即进入求值） |
| `@` | 跨协程消息：挂起本协程，恢复目标协程并传值 |
| `\^` | 特殊标识符：指向"恢复本协程的协程"的 handle |

## 帧树与标识符解析

所有求值发生在一棵**帧树**上（类似文件系统树）：

- 每个 `{}` block 求值时在帧树上产生一个新节点；
- 标识符解析走**显式路径**（`.` 向下，`..`（暂定符号）向上），
  不存在隐式环境链；
- `allocate p` 把求值挂接为调用处节点的子树——但仅当 `p` 的体以
  `{}` 开新 block 时才产生新节点；否则 `p` 体内的一切 `$symbol`
  都**在 allocate 处的节点上解析**（就地求值，不开新作用域）。
- `new p` 另起一棵树，默认隔离：`p` 的自由标识符在新树的
  对应节点解析，不允许解析到任何运行期栈帧（静态检查），
  保证协程环境不透明。新树不自动挂载全局环境；
  需要的能力由创建者显式注入（见"模块与导入"）。

由此"动态作用域"被驯化为**显式导航**：被调用者访问调用者的
局部值必须写成可见的上溯路径，不存在意外捕获。

## allocate / new 对照

| | `allocate p` | `new p` |
|---|---|---|
| 栈 | 当前协程的栈 | 新协程自己的栈 |
| 环境 | allocate 处的节点（或新开子节点） | 全新环境（默认隔离，能力显式注入） |
| 求值时机 | 立即进入 | 立即进入 |
| 生命周期 | 词法作用域（帧随 block 弹出） | GC |
| 与外界的通道 | 帧树路径 + 词法可见性 | 仅 `@` / `\^` |

## `\^`：恢复者 handle

`\^` 是一个特殊标识符，绑定到**恢复本协程的协程的 handle**。
handle 是普通值，可以：

- 调用它：`\^@v`（把控制权连同一个值交还给恢复者）；
- 访问它的栈帧（经 handle 在帧树上导航）；
- 存储、传递（协程可以持有其他协程的引用）。

协程栈帧互相隔离；一切信息交换经 `@`/`\^` 传值、
经 handle 显式访问对方帧，或经显式注入的只读模块引用。
不存在隐式共享通道。

## 函数 = 不挂起的 allocate 子程序

"函数调用"不是机制，是模式：

- **函数**：从不挂起的 `allocate` 子程序。编译器词法可判定
  （挂起点必须词法可见，不允许藏在动态分派后），
  退化为普通栈帧压栈，零开销。
- **参数是协议不是机制**：语言不提供参数列表。
  标准库定义 `Proc` 形状 `{ in: mutable _, body: prototype }`，
  调用糖 `f(x)` 展开为 `f.in = x; $(allocate f.body)`。
- **入口拷贝纪律**：body 的第一句把共享交接槽拷贝为帧私有局部值
  （`n := $fact.in`），保证可重入/可递归。
  交接槽只在"写入 → allocate → 拷贝"的同步无挂起窗口内使用，
  协作式调度下该窗口原子。
- **递归**：绑定默认允许自引用（`f := ^(... f ...)`），
  立即值的自引用由编译器拒绝。

```
fact := {
    in := allocate _,
    body := ^{
        n := $fact.in;
        1 if n <= 1
        else {
            fact.in = n - 1;
            n * $(allocate fact.body)
        }
    }
}
fact.in = 5; r := $(allocate fact.body)   !- => 120 -!
```

## 捕获（capture）

内核不提供捕获机制，由标准库分两层承载：

1. **值捕获**：闭包 = 普通对象 `{ env: {拷贝的字段}, code: ^(...) }`，
   代码经 `\this.env.x` 访问。由宏扫描自由标识符自动生成。
2. **可变捕获**：被捕获的 cell 需要非词法生命周期 → 用协程承载
   （`new` 一个持有状态的 cell 协程，GC 管理生命周期），
   闭包持有其引用，经 `@`/`\^` 读写。
   stdlib 提供 `cell` 构造器与读写糖。

统一视角：**闭包是对象，对象的可变状态是协程，协程由 GC 托管。**

## 全局环境、模块与导入

**全局环境 = 编译期值空间（见 01-comptime），只读，天然去重。**
不存运行期模块实例 cache——模块在编译期求值完毕，
经固化进入二进制，全程序共享同一只读实例。

- **静态导入**：`std := allocate compile [[]]new import@"std"`。
  `import` 不是语法/关键字，而是编译器在编译期提供的
  capabilities（与 `read` 同级）；`allocate` 表示为std分配一个空间， `compile` 指示右侧`new`/`import`求值发生在编译期；右侧 `import` 产生一个prototype；`new` `import` 表示在编译期为这个prototype分配空间，`$` 产生右值传递到运行期。
  import产生的值缓存 → 去重是求值缓存的自然结果。
- **模块不持可变状态**：模块 = 纯代码与常量。
  可变对象由外部持有者显式管理，共享可变状态在代码里
  永远有明确的持有者。
- **动态导入**：由标准库实现（`read` + `allocate`），
  其本身是一个经 `compile import` 静态导入的模块。
  与静态导入是两种明确区分的机制，互不混淆。
- **多文件独立编译**：`.proto` 模块是不固化环境的纯原型，
  对外部的引用保持为自由标识符，在导入方求值时解析；
  不存在"每个编译单元自带全局环境"的冲突。
  良构模块在头部以形状约束声明 import 期望（模式匹配，非语法）。
- **协程的能力注入**：`withimport` 是标准库 helper（非关键字）：
  在 caller 环境执行，值捕获所需的只读模块引用与目标原型，
  返回一个包装原型——先在新协程中绑定捕获的 imports，
  再 `allocate` 原原型。捕获的是编译期只读对象，
  无生命周期问题、无跨栈可变引用。
  与 01 的"元层 capabilities 显式传入"是同一哲学在运行层的镜像。

## 程序入口

`main` = 运行时以全局环境为初始环境 `allocate` 入口原型。
main 的体以 `{}` 开新节点，其局部值住在自己的帧中，
照常 `mutable`；全局环境的只读性不限制 main 的可变性。

## GC 边界

GC 只管理协程对象（独立生命周期、可互相持有引用、可能成环）。
`allocate` 帧全部走词法作用域，不进 GC。
不创建协程的程序零 GC 负担。

## 显式条款（诚实清单）

- 交接槽纪律不由机制强制；编译器可对"潜在重入点后读取共享槽"
  给出静态警告，但不构成错误。
- 若未来引入抢占式线程并共享 `Proc` 对象，交接槽会竞争；
  缓解方向是交接槽协程私有化，当前不做，记为已知边界。
- 原型的自由标识符解析是 binding-time 问题（见 01-comptime）：
  缺省按动态结构编译；allocate 处与原型都静态可知时，
  折叠为静态帧偏移，恢复零开销。

## 词汇表

- 退役：`new` 之外的函数定义语法、`?` 输入标识符、
  隐式 `arguments` 对象、隐式环境链。
- 复用：`{}`（block = 帧树节点 = 环境边界）、
  `\^`（从"隐式挂起点"精确化为"恢复者 handle"）。
- 新增约定（非机制）：`Proc` 形状、入口拷贝、
  交接/上溯路径的显式书写。
- 非关键字：`import` 是编译期 capability，`withimport` 是
  stdlib helper，模块头部 import 约束是普通模式匹配。
  这一层没有任何黑魔法。

## 验收用例（自检清单）

1. 宏实现 `proc^(n => ...)` 糖：展开为 Proc 对象 + 入口拷贝 + 递归糖。
2. 宏实现值捕获闭包：扫描自由标识符 → 生成 env 对象 + 路径重写。
3. `cell` 协程实现可变捕获，两个闭包交叉读写同一 cell。
4. 生成器：`new` + `\^@` 实现 `yield`，消费者经 `@` 驱动。
5. 静态检查：词法不可见挂起点的子程序拒绝按函数优化；
   `new` 的原型引用运行期栈帧 → 编译错误。
6. `withimport`（stdlib helper）：新协程默认不可见 caller 的
   模块；经 withimport 注入后可用，且注入的是同一只读实例。
7. `compile import` 去重：两处导入同一路径，得到同一对象；
   模块头部形状约束不匹配 → 编译期链接错误。

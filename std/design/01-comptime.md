# 01 - Comptime 与阶段边界

前置：无（系列总纲）
后续：[02-evaluation.md](02-evaluation.md)、[03-symbols-locations-matching.md](03-symbols-locations-matching.md)、[04-control-flow.md](04-control-flow.md)、[05-ownership.md](05-ownership.md)

## 一、核心原则

语言只有一个求值器。代码可在编译期或运行期被求值，两者的求值规则、控制流与所有权语义完全相同。
`compile` 不是值上的属性，而是**求值发生的时机**。

## 二、阶段分层

| 层级 | 执行时机 | 触发方式 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **元层** | 编译期（必须） | 构建脚本入口、顶层 `compile` 块、编译器指令 | 构建配置、模块导入、代码生成、编译期诊断 |
| **程序层（静态）** | 编译期（编译器尽力） | 常量折叠成功；`compile` 标注强制 | 单态化、静态布局推导、编译期预计算 |
| **程序层（动态）** | 运行期 | 默认；静态操作作用于动态值时自动插入运行期检查 | 常规程序执行、动态装箱与分派 |

- **元层隔离与能力注入**：原生在编译期执行的元层代码与“被折叠到编译期执行的普通程序代码”明确区分。元层能力（IO、文件系统、`import`、编译器内省）通过显式的 capabilities 普通对象传入，默认沙箱化。
- **确定性与可缓存**：单次编译期求值内部允许拥有局部可变状态（`mutable location`）；但跨求值缓存与跨阶段传递只允许不可变的固化值（见第四节），因此编译期求值天然可缓存、可测试、IDE 可安全执行。

## 三、与动态类型的关系

- 语言允许动态类型，因此语言层面“必须编译期已知”的语法位置趋近于零。
- 类型注解、泛型实例化、数组长度等位置**不强制要求**编译期已知；它们只是“若编译期可折叠则解锁单态化与静态内联布局”的优化机会。
- **折叠成功** → 单态化 + 静态内存布局 + 消除运行期检查；**折叠失败** → 装箱（胖指针）+ 动态分派 + 运行期检查。
- **强制断言**：用户可用 `compile` 显式约束某位置必须在编译期求值完成；若折叠失败则直接报编译错误，绝不静默退化为运行期求值。
- 静态类型与动态类型是同一份代码在不同折叠成功率下的两个编译结果。

## 四、阶段边界规则

1. **固化（Reification）**：编译期求值结果跨阶段进入运行期时，只允许三类不可变值跨越边界：
   - **基础/复合 `value`**：深拷贝为二进制常量段数据；
   - **`frozen` 对象**：整棵只读对象快照固化进常量段；
   - **`prototype`（代码值）**：固化为可序列化的中间表示（IR）并参与后续编译。
   - **严禁固化**：owned `location`（无论是否 `mutable`）、裸指针、外部资源句柄、活跃帧 handle（`	his`）及协程 handle（`\^`）。
2. **阶段结束清理**：单次 `compile` 求值结束时，其创建的 owned `location` 树按 [05-ownership.md](05-ownership.md) 的销毁规则完整执行析构（含 `\destroy` 钩子与 `%drop`），仅固化值留存。
3. **单向性**：`compile` → `runtime` 单向不可逆。运行期值绝不能流回编译期（语言内核显式排除运行期 JIT）。
4. **步数上限**：编译期求值不追求理论可判定性；编译器设置求值步数上限，超限时报错并输出普通调用栈。

## 五、类型系统接口

- **类型即编译期值**：`type : type`（v1 有意保持该自指设定，不做 Universe 层级切分）。
- **泛型即普通函数**：泛型函数 = 参数中包含类型的普通函数；泛型类型 = 返回类型值的普通函数。
- **单态化与动态表示**：编译期已知类型参数时执行单态化；动态类型路径保留运行期形状（shape）描述以支持运行期检查与分派。

## 六、阶段与可变性词汇表

求值阶段与位置可变性完全正交，全语言仅用两个修饰词：

| 标注 | 作用目标 | 含义 | 缺省行为 |
| :--- | :--- | :--- | :--- |
| `compile` | 求值时机 / 模式约束 | 强制编译期求值完成 | 编译器尽力折叠，不作硬性保证 |
| `mutable` | `location` 契约属性 | 允许在 `live` 状态下反复覆写或重填 | 默认 `immutable`（仅允许 `uninitialized → live` 单次初始化） |

- **废弃旧词**：`constant`（混淆时机与可变性）、`variant`（缺省状态无需标注）、`comptime`（改用自解释的 `compile`）、`static`（消除 C 系多义性）、`readonly`（缺省即为不可变）、`%seal`（因 `uninitialized` 支持单次初始化，无需运行期改变可变性属性）。

用法示例：

```
!- 1. 元层块：编译期执行构建逻辑 -!
compile { ... }

!- 2. 位置约束：要求参数 n 在编译期已知 -!
n : compile usize

!- 3. 编译期求值并绑定为运行期不可变位置（auto-box） -!
size := compile f(x)

!- 4. 编译期求初值、运行期可反复修改的位置 -!
x := allocate mutable integer;
\x = compile f()
```

## 七、验收用例（自检清单）

1. **编译期 `printf`**：在编译期解析格式串，并按参数类型生成对应的格式化 `prototype` 代码固化到运行期。
2. **编译期生成只读查找表**：`compile` 块中用 `mutable location` 计算完美哈希表，冻结为 `frozen` 对象或 `value` 后跨阶段供运行期只读引用。
3. **编译期反射 `derive(Serialize)`**：读取任意类型的编译期 shape 结构，生成并返回序列化函数 `prototype`。
4. **编译期构造 `location` 试图直接跨阶段固化**：编译器静态拒绝；只读 `value`、`frozen`、`prototype` 正常固化。
5. **编译期 RAII**：`compile` 块内创建的资源与 `defer` 守卫在编译期块结束时按运行期完全相同的逆序规则执行 `\destroy`。

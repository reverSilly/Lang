# Comptime 设计记录

状态：草案（2026-10-24，2026-10-25 按 06 §9 回写固化边界）

> 固化边界已改为：只允许 value、frozen 对象、prototype/code 值跨阶段；
> 禁止固化 owned mutable location、裸指针、资源、frame handle。
> 共享可变 comptime 堆只存在于单次求值内；跨求值缓存必须是不变固化值。
> 旧版“指针/引用按对象图整体固化”“mutable location 固化”作废。

## 核心原则

语言只有一个求值器。代码可在编译期或运行期被求值，两者语义完全相同。
comptime 不是值上的属性，而是**求值发生的时机**。

## 阶段分层

| 层 | 执行时机 | 触发方式 |
|---|---|---|
| 元层 | 编译期（必须） | 构建脚本入口、`compile` 顶层块、编译器指令 |
| 程序层（静态） | 编译期（编译器尽力） | 常量折叠成功；`compile` 标注强制 |
| 程序层（动态） | 运行期 | 默认；静态操作作用于动态值时自动插入运行期检查 |

- **元层**：原生在编译期执行的代码（构建脚本、编译器配置、`@compileError`）。
  与"被挪到编译期执行的普通代码"明确区分。
- 元层能力通过显式的 capabilities 值传入（IO、文件系统、编译器内省），
  默认沙箱化。单次 comptime 求值内可以有可变状态；跨求值缓存只允许
  不可变固化值，因此缓存不依赖共享可变堆。capabilities 是普通对象。
- 表中“静态/动态”描述的是折叠机会，不是两套语言语义；静态优先还是动态
  优先的立场由 07 的类型系统裁决（当前仍有 02/03 的静态承诺依赖它）。

## 与动态类型的关系

- 语言允许动态类型，因此语言层面"必须编译期已知"的位置趋近于零。
- 类型注解、泛型实例化、数组长度等位置**不要求** comptime；
  它们是"若 comptime 满足则解锁静态布局/单态化"的优化机会。
- 折叠成功 → 单态化 + 静态布局；失败 → 装箱 + 动态分派。
- 用户用 `compile` 断言强制：折叠失败即编译错误，而非悄悄退化。
- 静态类型与动态类型是同一代码在不同折叠成功率下的两个编译结果。
- 若保留动态类型，第一版就必须有运行期类型表示；"只做单态化，
  类型擦除留待后续"与此冲突，挂账 07。

## 阶段边界规则

1. **固化（reification）**：只允许 **value、frozen 对象、prototype/code 值**
   跨阶段进入运行期。value 深拷贝为二进制常量；frozen 对象整体固化且不可变；
   prototype/code 值需要定义可序列化的 IR 与再编译路径（见待办）。
   禁止固化 owned mutable location、裸指针、资源、frame handle。
2. **单向性**：comptime → runtime，不可逆。运行期值不能流回编译期（JIT 显式排除）。
3. **不终止**：不追求可判定性。编译器设步数上限，超限报错并给出普通调用栈。
4. **阶段结束**：comptime 的 owned 树按 06 §6 销毁；跨边界的只有固化值。

## 类型系统接口

- 类型是编译期的值（`type : type`）。这是**有意的不一致**（Girard 悖论），
  v1 不做 universe 分层；需要在诚实清单中明示，而不是当成 bug。
- 泛型函数 = 参数中出现类型的普通函数；泛型类型 = 返回类型的函数。
- 第一版只做单态化；动态类型所需的运行期类型表示/擦除属于 07。

## 词汇表

阶段与可变性正交，各一个词，共两个：

| 标注 | 含义 | 默认 |
|---|---|---|
| `compile` | 强制编译期求值 | 编译器尽力折叠，不保证 |
| `mutable` | 可变 | 不可变 |

- `:=` 只命名 location（06），因此不存在 `compile mutable x = ...` 这种
  旧绑定写法。组合示例：`x := allocate mutable integer` 之后
  `\x = compile f()`（编译期求值、运行期可写），或
  `x := allocate ^(compile f())`（编译期求值并固化为不可变初值）。
- 废弃旧词：`constant`（混淆了时机与可变性）、`variant`（缺省状态无需标注）、
  `comptime`（合成词不自解释）、`static`（C 系历史歧义）。
- 同一编译器进程中**单次** comptime 求值共享堆，受词法作用域约束；
  跨求值只共享不可变固化值，取代旧设计 `constant` 的“统一值空间”。

用法示例：

```
compile { ... }              // 元层块：编译期执行（构建脚本等）
n : compile usize            // 位置约束/pattern：此处要求编译期已知
size := allocate ^(compile f(x))  // 编译期求值并固化为不可变初值
```

## 验收用例（自检清单）

1. comptime 实现 `printf`：解析格式串 + 按参数类型生成代码
   （依赖 prototype/code 固化机制）。
2. `compile` 块生成完美哈希查找表 → 固化为常量 value/frozen 供运行期引用
   （检验元层→程序层通道；不允许固化 mutable location）。
3. `derive(Serialize)`：读任意类型的形状生成序列化代码
   （需要 codegen/IR 固化路径）。
4. 编译期正则 → DFA（压力测试）。
5. comptime 构造 mutable location 并试图固化到运行期：编译错误；
   只读数据、frozen、prototype/code 可固化。
